# リファクタリングの手順

外部の挙動を維持する構造変更として扱います。挙動変更やmigrationは別途scopeを明示します。

1. 影響を受けるconsumerとimportを調べ、維持する外部契約と確認方法を定める。比較が必要な場合は変更前の挙動を記録する。
2. ファイル分割では [責務分割の基準](../rules/coding.md#file-responsibility-boundaries) に従い、配置先と必要最小限のinterfaceを決める。
3. ファイル移動・API変更・挙動変更・整形の差分を個別に確認できる単位にする。
4. 互換性のある境界を先に作り、型を確認できる状態を保ちながらconsumerを段階的に移す。移行中の循環importやfeature間依存も確認する。Firestore / Storageの契約を変更する場合は、データ移行の要否を判断する。
5. 外部契約が維持されていることを [検証ルール](../rules/testing.md) に従って確認する。性能改善では測定方法と変更前後の結果を示す。
6. [文書の更新方針](../../AGENTS.md#文書の責務と更新) に従い、該当箇所を更新する。
